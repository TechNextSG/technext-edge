AI / WhatsApp Channel · PostgreSQL Schema

Physical PostgreSQL schema for WhatsApp AI Channel transitioning from Redis KV to Supabase PG 17+. Features 9 dedicated AI channel tables anchoring directly into team core tables (scenario, revision, app_setting). Foreign keys connect column to column with explicit referential actions.

THE FOCAL CASCADE

Deleting a scenario cascades into bot enquiries

ai_enquiry.scenario_id references scenario.id via ON DELETE CASCADE — purging an enquiry removes its review state and draft notes. Similarly, deleting a revision cascades into ai_extraction telemetry. Conversation purges cascade to messages and handoffs.

Distributed lease locks & partial uniqueness

  • Lease without transaction: lock_token and lock_until on wa_conversation guard turns without open connection pool pins during 20s LLM roundtrips.
  • Partial unique index: unique (phone) where ended_at is null prevents multiple active threads per guest.
  • Handoff queue: unique (phone) where resolved_at is null preserves historical escalations while preventing duplicate staff pauses.

Zero KV dependency & AES-256-GCM vault

API keys for Gemini and DeepSeek reside in ai_provider_key encrypted with AES-256-GCM (bytea), mirroring team secret standards. AI configuration changes are immutably logged into ai_setting_audit. RLS is enforced across all 9 tables with zero public PostgREST exposure.
